FE-36 adds one GET /api/public-records?division= per completed card mount/scope transition, with simultaneous request sharing. Existing route uses readPublicRecords -> readPromotedCivicData(CURATED_READER_RECORD, US:public-records:<exact division>). Query is exact scope, never all places. Body filtering is local to that division. Each missed server cache can read its promotion and candidate proof; unchanged-pointer refresh reads identity. An empty scope reads the scoped missing pointer once per cache TTL. Client reopening after the first request completes issues another GET; actual Neon cost depends on server cache/instance reuse.

Estimate in BYTES, not a fabricated bill: with projected response bytes P_s, proof bytes C_s, identity bytes I_s and extra validation/predecessor bytes A_s, cold fallback cost per scope is P_s+C_s+A_s; an unchanged refresh is I_s; warm cache/served edge is0Neon bytes. Incremental hourly bytes = sum(cold misses_s*(P_s+C_s+A_s) + unchanged refreshes_s*I_s + absent misses_s*missing-pointer bytes).
