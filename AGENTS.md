Civic app, two halves. Consumer side shows what's on a user's ballot with

## The order of every trade

**Correct first. Fast second. Nothing third.** Perfection and speed are both
mandatory, and when they collide, correct wins — always. A fast wrong answer in
this product is a false claim about a government, and that is the one failure it
cannot survive. Never ship partial data as complete, never let green stand in
for verified, never trade an honest gap for a plausible guess. Data is the
trophy. Public records are the product's birthright. Difficulty is friction, not
refusal. Go get it.

## The acquisition doctrine

*(Adopted 2026-08-29, the author's directive. RULING 205, RULING 206, RULING 207
and RULING 208, extended 2026-09-01 by RULING 229, which fixes the
DENOMINATOR the doctrine acquires against. Operative text:
`docs/governance/policies/discovery.md`,
`docs/governance/policies/sources-licensing.md`,
`docs/governance/policies/tracker-workflow.md`. This is the transparency
mandate's operative half — the mandate says go and get it; this says what that
obliges, and the only three things that may ever end it.)*

```
IT EXISTS = GET IT
ROUTE FAILED             = TRY ANOTHER PATH
ROUTE BLOCKED            = TRY ANOTHER PATH
EXTRACTION FAILED        = TRY ANOTHER EXTRACTION PATH
API/CREDENTIAL REQUEST   = PARALLEL ESCALATION + CONTINUED HUNT
VENDOR != RECORD                URL != RECORD
ONE ROUTE SUCCESS != SOURCE UNIVERSE COMPLETE
NEEDS SEAN != STOP
EFFORT != EVIDENCE              EXHAUSTION != DISPOSITION
THE WORKER MAY STOP; THE OBLIGATION DOES NOT
```

**If a public civic record exists, get it.** "Get it" is the whole chain —
`DISCOVERED → ACQUIRED → EXTRACTED → NORMALIZED → CANONICALLY_LINKED →
QUERY_RETRIEVABLE → READER_VERIFIED` — and **no upstream success implies a
downstream one**. A route can fail; the record obligation does not. A route
disposition closes a RouteTask and never closes the record obligation, so
`ROUTE_BLOCKED → NO_SOURCE_FOUND → COMPLETE` is forbidden for a record known or
strongly expected to exist. When the known portfolio is spent and the obligation
is still open, the obligation is to find the next public-access method: having
run out of KNOWN methods is not having run out of methods. (RULING 205.)

**Three closes, and there is no fourth.** Acquired and reader-answerable;
affirmative source-backed evidence about the RECORD ITSELF — not created, not
yet published, lawfully withheld, destroyed under retention, or not obtainable
publicly — where **our failure to retrieve it is never that evidence**; or every
machine-executable public route worked with only a human or offline act left,
which is **PUBLIC RECORD STILL OWED — HUMAN/OFFLINE ACCESS REQUIRED** and keeps
the obligation live. Persistence is never intrusion: no bypassed authentication,
no misused credentials, no exploited vulnerability, no non-public systems. Do
not let one lock define the public information universe.

**The vendor is not the record.** Granicus, Legistar, CivicClerk, BoardDocs,
Diligent, CivicPlus, Hyland and every system like them are filing cabinets. The
model is `GOVERNMENT → RECORD → REPRESENTATION(S) → ROUTE(S)`, and the record is
this body, this exact meeting, this exact version — never the URL that served
it. A restriction or failure on one document host is a fact about that host, not
about the API, the portal, the accessible rendering, an alternate first-party
copy, an archive, another custodian, or the record. **One representation lost
means resolve another representation of the same record**, which makes an
artifact held from a route later found unavailable a REPLACEMENT obligation
rather than either a loss or a blessing. (RULING 206.)

**One successful route never collapses the source universe.** Materially
distinct representations carry different facts, so an API 200 never retires the
PDF, a readable PDF never retires the API, and a meeting page is a branching
surface rather than a URL to record and leave. **An adapter is a route
portfolio, not one fetch function**, and its known routes are a floor.
Reconcile every material representation into one canonical record with
provenance, observation time and supersession; deduplicate exact duplicates and
use change detection, but never skip a materially DISTINCT representation
because another route already returned 200. (RULING 207.)

**An access escalation is a parallel lane, never a stop.** Where a token,
account, export, feed or quota would materially help, name it precisely —
provider, mechanism, record class, scopes, what it unlocks, and what continues
without it — and keep working every other executable path meanwhile. **NEEDS
SEAN never closes, pauses or satisfies the obligation the row is about**, and
one blocked record never freezes the rest of the hunt. No secret is ever pasted
into chat, a prompt, a row, a commit, a fixture or a log. (RULING 208.)

**Acquire to the authoritative source universe; project to the reader.** A ZIP,
address, pilot or currently enabled reader location may prioritise acquisition
ORDER and may never define the acquisition DENOMINATOR. Where a source authority
governs a state, acquire the state; where it governs a county, municipality,
district or other bounded jurisdiction, acquire that authority's complete
applicable universe. **Reader location determines applicability and display
only.** Candidate enrichment is keyed to the canonical statewide
candidate/contest universe, never to the visible ZIP, and local filing regimes
are enumerated as durable jurisdiction obligations before a reader needs them.
The invariant is **ZERO REDUNDANT INTERNET HUNT WHEN A NEW ZIP IS ACTIVATED**:
anything absent when a ZIP activates already exists as an identifiable
pre-existing obligation, never as new work caused by adding the ZIP. Three
layers, kept apart — ACQUISITION (the source-authority universe, no ZIP
dependency), IDENTITY (candidate → contest → office/division → party → filing
authority → committee), PROJECTION (a ZIP picks applicable candidates from the
registry and asks the corpus). A reader snapshot may hold only what a page
applies to; its SOURCE CORPUS may never be generated from that page's candidate
list. "Already acquired" does not mean "in Git" — normalized reader-ready data
in the versioned snapshot, canonical records in DB or object store, raw
artifacts in the durable vault, methods and provenance and denominators
committed. The autonomous worker graph owns the unresolved remainder, not a
future author prompt. (RULING 229.)

## The cross-cutting non-negotiables

These bind everywhere, in every domain. The detail and the reasoning are in the
policies; what is here is the part no session may ever need to look up.

**Never generate a candidate position.** Every position, vote or stance rendered
to a reader carries a source record pointing at a specific statement, roll-call
vote, filing or questionnaire response. If no source exists, the field is null.
Never infer from party, endorsements or similar candidates. This binds
LLM-written summaries too: a summary paraphrases a cited source, never fills a
gap.

**The product never tells anyone how to vote.** No ranking, no recommended
ballot, no match, fit, alignment or compatibility score, no ordering by anything
but a neutral criterion. A reader asking for a recommendation directly is not an
exception, and neither is a well-sourced transparent one.

**Show everything we find.** Collection state never governs display. There is no
threshold, no completeness bar, and no circumstance under which a candidate, a
contest or a field is suppressed because something else is missing. Completeness
is a property of the HUNT. The correct response to an incomplete hunt is more
hunting. (RULING 26, RULING 27.)

**Acquisition without promotion is inventory, not product** (RULING 224). An
acquisition obligation does not close when evidence reaches the vault; it closes
when the reader-facing surface reflects the acquired truth OR renders the honest
gap state. While unattended promotion is OFF, the pipeline still runs
AUTOMATICALLY through normalization and snapshot to a STAGED, promotion-ready
state, and session shipping carries the last mile. **Held data with no live
promotion tail is a defect** — retroactively, so every held corpus either flows
to a surface, stages promotion-ready, or carries an argued reason it cannot.

**Reader-facing civic truth changes through exactly one door** (RULING 242): the
nightly window, run by the standing runner on the machine's own clock at 04:00
America/New_York, over a typed pipeline — `SCOUTED → CONFIRMED → VERIFIED →
AUDITED → APPROVED_FOR_PROMOTION`, or `REFUSED` with its reason at any stage.
Scouts, Acquirers, Parsers and Detectives never write reader truth. Until the
activation gate opens the window runs in SHADOW and promotes nothing; the legacy
daily refresh is the named transitional path, retired source by source under
`docs/migration-inventory.md`.

**Provenance is machine-owned** (RULING 243). When a record was retrieved, from
where, under what permission verdict, in what record class and on which
artifacts is written by the machine from the Attempt, artifact, obligation and
permission records; the model's statements about those facts are recorded as
claims and never become durable provenance.

**Every session report leads in reader terms** (RULING 225), in this order: what
a reader can now see that they could not before; what workers advanced
unattended; what genuinely requires the owner. Infrastructure counts come
afterward. If a reader loading the page would see what they saw yesterday, it
does not go in the lead.

**A render default may never manufacture a claim.** A null renders as its NAMED
GAP, on every surface, always — and the name says WHOSE gap it is. "We haven't
recorded this yet" is a fact about us; "not in this chamber for this vote" is a
fact about them. They may never render as the same sentence.

**The product never announces its own failure.** State what is known, offer the
narrowing, move on. The ATTRIBUTION above is required; a verdict on ourselves is
struck. (RULING 139.)

**An operation that can return nothing must be asked what it returned**, and a
partial that reconciles is still a wrong answer (RULING 100). A zero-row
extraction is a FAILED extraction, never an empty document.

**A finite attempt count never earns an absence.** Five moves, seven tiers, N
routes, every manifest entry — floors and instruments, never completion
conditions. A session with no further avenue says **"I have run out of ideas"**,
which is a claim about the session, never "this is not published", which is a
claim about a government. (RULING 170, RULING 184.)

**The collection stores never join.** No store carries a column that could join
to another, and there is no mapping table between any pair. Proven over VALUE
SPACES, never column names (RULING 132).

**No user-to-user surface.** Reactions are write-only from the reader's
perspective — stored and aggregated, never rendered back to any user, including
in aggregate.

**Aggregate-only is a boundary, not a storage rule** (RULING 226). Anonymous
event-level rows may exist AT REST exactly as
implemented — no identity, no free text, no read API. Anything ever EXPOSED,
RENDERED or LICENSED is aggregate-only, without exception. Changing any of those
three at-rest properties reopens the question rather than inheriting the
ratification.

**The owner's identity is one Google address** (RULING 245). Administrative
access authenticates through Sign in with Google for exactly the enrolled owner
address, verified server-side; a shared secret is never a login path except as
a documented, rate-limited, incident-logged break-glass under RULING 238.

**Collect the minimum.** Zip or address for district resolution, an email for
account identity. Adding a field to the user model is an ask-before.

**Reader friction is a defect**, with exactly three exceptions, each checkable by
number: the transparency disclosure at reaction capture, the optionality of the
narrowing prompt, and anything constituting consent to collection.

**Reader surfaces speak plain language.** No OCD-ID, no enum value, no
`NO_SOURCE_FOUND` reaches a reader.

**An agent does not know today's date.** Every stamp entering every document
comes from `pnpm stamp`. A plausible date is a fabrication, and it misdates the
rule every later decision was supposedly made under.

**A generated artifact is never hand-edited** (RULING 92), and fixing a
generator is not finished until its output is regenerated and diffed
(RULING 102).

## Discovery, in one page

The detail is `docs/governance/policies/discovery.md`. What binds everywhere:

**The universe of owed subjects may be bounded. The universe of methods is
not.** The effort permitted to complete an owed item is not arbitrarily capped.
A workstream may have a denominator; the method is permanently open-ended.
(RULING 177.)

**And the bound is on SUBJECT, never on effort.** A discovered route enlarges
the active graph only when it plausibly advances an owed question — a
governmental body, an official, a meeting, an election, a filing, another
authoritative publisher, an official record, evidence for an owed fact, a new
governmental layer, or a new source class. **A government page does not
recursively make every hyperlink on the internet owed.** That is what keeps
discovery finite without capping how hard an eligible edge is worked, and it is
the only bound there is. `lib/workstate/eligibility.ts`.

**Inherit everything. Assume it is incomplete. Learn what this place teaches.
Keep the learning. Reapply it where else it fits.** A method that works across
43 states is the method learned so far, never *the* method. A new route is
PROJECT knowledge, persisted, classified by portability, inherited by every
later jurisdiction — and it **mechanically reopens** prior conclusions it would
have applied to. (RULING 178.)

**No manifest, route list, source taxonomy, government-type taxonomy, platform
taxonomy or retrieval vocabulary is ever complete.** Each represents WHAT THE
PROJECT KNOWS NOW.

**Discovery is a tree, not a ladder** (RULING 52), **absences expire**
(RULING 53), **every twig is named** (RULING 57), and **convergence is
versioned** — `CONVERGED_AS_OF` means every currently eligible avenue has a
disposition under the current method version, never that no other source exists
(RULING 179).

**A blocked route may never become a blocked fact.** `BLOCKED_CURRENTLY`,
`REQUIRES_NEW_ADAPTER`, `RECORDS_REQUEST_PENDING` and `RECHECK_DUE` are real
states. A CAPTCHA is not absence; missing tooling is not absence. (RULING 184.)

**Permission state and transport state are orthogonal.** "Could not fetch
robots.txt with this client" is never "robots disallows this host". `CANNOT_TELL`
fails safe for the route and keeps hunting the fact by other branches.
(RULING 182.)

**A lead is not a body.** Detectors produce CANDIDATES. Coverage rises only
through verified and promoted bodies, and no candidate count may substitute for
the promoted-body count. (RULING 183.)

## Sessions, and what "done" means

**A session runs unattended. Nothing it runs may be able to ask it a question**
(RULING 146). A decision that is genuinely the author's becomes a Needs Sean row
and the session keeps going.

**Escalation without reconciliation is prohibited** (RULING 227). A row may not
ENTER Needs Sean without either a machine-verifiable predicate that is rechecked
on EVERY tracker generation and AUTO-RESOLVES the row when it goes false, or an
explicit `NOT_MACHINE_VERIFIABLE` marking carrying a decision card. Every card
states what is needed, the options, the consequence of each, and the row's AGE.
A queue with no mechanism capable of noticing that a blocker stopped being true
will present the author with stale blockers as the current state of his own
project, which is what it did.

**Three independent statuses, and confusing them is a reporting defect**
(RULING 180, amended by RULING 189):

```
SESSION:    COMPLETE
            CLEAN_HANDOFF_AUTHOR_STOP
            CLEAN_HANDOFF_EXTERNAL_STOP
            EARLY_HANDOFF
            FAILED_CLOSEOUT
WORKSTREAM: OPEN | COMPLETE_AS_OF <date>
GRAPH:      EXPANDING | CONVERGED_AS_OF <date>
```

**A session does not measure itself** (RULING 189). It does not estimate context
used or remaining, narrate approximate percentages, monitor its own context as a
work-management signal, stop because it believes a threshold was reached, or
call itself early on guessed capacity. There is no threshold, and no proxy for
one — not elapsed minutes, token guesses, message counts, command counts, commit
counts, fatigue, or a work quota.

**The rule, entire:**

```
DO THE WORK THAT WAS ASKED FOR.
KEEP WORKING WHILE AUTHORIZED EXECUTABLE WORK REMAINS.
STOP WHEN THE REQUESTED WORK IS ACTUALLY COMPLETE, WHEN THE AUTHOR EXPLICITLY
STOPS OR REDIRECTS THE SESSION, OR WHEN THE ENVIRONMENT ITSELF ACTUALLY
PREVENTS CONTINUATION.
```

`CLEAN_HANDOFF_EXTERNAL_STOP` is never INFERRED; **one blocked item does not
qualify while other authorized work exists — skip forward.** `EARLY_HANDOFF` is
what a voluntary stop with owed work is called, however excellent the handoff.

**MERGE CADENCE IS NOT SESSION CADENCE.** RULING 1 governs shipping — verify
locally, accumulate, ship once at the real end. **The planned merge having
happened is not a reason to stop.** Delay the merge until the session is ready
to end.

**PERSISTED RESUMABILITY IS NOT PERMISSION TO STOP VOLUNTARILY.** Canonical
state exists so an interrupted session can resume, not so this one can end.

**DISCRETION COVERS HOW, NEVER WHAT** (RULING 223). Implementation choices and
lane ordering are the session's, entirely. Which Parts exist, which acceptance
criteria count, and what "done" means are the author's, entirely. *"I chose
depth over coverage"* is not a stop condition — it is an unrecorded amendment to
the brief. When capacity actually ends, the only lawful output is **UNFINISHED
SESSION** carrying the exact resume point and every unreached item BY NAME.
RULING 221 forbids discovery INFLATING the denominator; this forbids discretion
DEFLATING it. Same rule, both directions.

**The model does not award itself a status. The state does**
(`classifySessionStop` in `lib/workstate/types.ts`). Every non-`COMPLETE` close
records a specific `stop_reason`, whether the author stopped the session,
whether an actual external condition prevented continuing, and
`executable_owed_work_remaining` — derived, never asserted. A stop reason that
appeals to self-estimated capacity or to merge cadence cannot make a stop clean:
it is refused, and the refusal names the non-reason.

**The repository generates the handoff, not the model.** `pnpm workstream:close`
produces the exact cursor and the exact unresolved set from canonical state. The
model may explain it; it may not invent it. No "the rest", no omitted tail.

**Item completion is DERIVED from child state.** A model may not type "done"
while unresolved required children exist.

**A frontier is state, not a recipe for recreating state** (RULING 181).
`passes` and `budget` choose how much queued work to process; they never define
what work exists.

## A session is an engineering organization

**RULING 190 and RULING 191.** The author states desired product outcomes. The
session diagnoses, decomposes, delegates, executes, integrates and ships.

**WHEN TWO OR MORE AUTHORIZED EXECUTABLE WORKSTREAMS ARE MATERIALLY
INDEPENDENT, SAFE PARALLEL EXECUTION IS THE DEFAULT.** Serializing independent
work is a process defect, and the session names the dependency rather than
silently serializing the queue.

Before broad implementation, every session loads current governance for the
task, identifies the authorized executable work universe, builds a
dependency/conflict graph, identifies the independent workstreams, fans them out
using the **strongest parallel mechanism the environment actually supports**,
designates one integration owner, and keeps independent streams progressing
while another waits or blocks. The decomposition is PROPORTIONAL — two five-line
edits to one file are one workstream.

```
INDEPENDENT WORK          -> PARALLEL BY DEFAULT
TRUE DEPENDENCY           -> SERIALIZE AND NAME WHY
ONE WORKSTREAM BLOCKED    -> THE OTHERS CONTINUE
ONE WORKSTREAM DONE       -> READY_FOR_INTEGRATION, NOT SESSION DONE
TRACKER ROW CREATED       -> NOT WORK COMPLETION
LARGE PR / MANY FILES     -> NOT A STOP REASON
P0                        -> START IMMEDIATELY, NEVER FREEZE THE OTHERS
```

**A tracker row is a record of work, never a substitute for it.** If an item is
executable now, execute it now.

**The law names no vendor.** Subagents or parallel agents where they exist,
otherwise worktrees, branches, concurrent shells and processes, parallel
retrieval and parallel test jobs. Where only one thread genuinely exists the
obligation survives as interleaving. *"I cannot spawn another engineer"* is not
a dependency.

**Correctness still outranks speed.** The goal is MAXIMUM SAFE PARALLEL
THROUGHPUT, never the maximum number of branches. Two branches independently
rewriting one canonical store, or independently regenerating one generated
output, are refused by this rule rather than permitted by it.

**One integration owner, one combined head, one merge at the end.** Workstreams
own their code, tests and source data; the integration owner alone reconciles
the shared stores — canonical work state, the tracker, state and log, the method
store — and regenerates every generated artifact ONCE. A branch changes
canonical INPUTS. Branch-local green is necessary and never sufficient: only the
integrated head ships, and the cross-workstream interactions are tested there
because that is the only place they can fail.

**The verdict is derived, not claimed** (`classifyOrchestration` in
`lib/workstate/orchestration.ts`, run by `pnpm orchestration:check` over
`data/workstate/orchestration/`). Each workstream records its id, dependency ids
and the reason for each, the paths and data it owns, what it produces and
consumes, whether it is executable, and its disposition. **A dependency is
PROVEN only by an owned-domain overlap or a produces/consumes handoff** — an
edge backed by prose alone is reported UNPROVEN. Independent, executable, and
serialized with nothing checkable behind it is a FAILURE. PR size, branch
simplicity, conflict avoidance, convenience, unspecified caution, P0, and the
absence of subagents are refused as justifications by name.

**What it cannot do is stated, not hidden:** wall-clock concurrency is not
observable here, so the guard checks the plan's shape and every serialization's
justification. Recorded evidence — worktrees, branches, agent ids — is
corroboration, never proof.

## Stack

**This section names DECISIONS, never versions.** A framework version written
here goes stale the next time anyone runs an upgrade, and a stale constitution
is worse than a short one. Shelf-life content lives where it is authoritative:
**`package.json` and `pnpm-lock.yaml`** for what is installed, **`netlify.toml`**
for how the deploy builds, **`next.config.ts`** for what the build does,
**`drizzle.config.ts`** for the database wiring, and
**`lib/ops/refresh-cadence.ts`** for what runs when.

What does not drift, and is therefore law:

- Next.js (App Router) + TypeScript + React.
- Tailwind + shadcn/ui; the design tokens are committed (`docs/DESIGN.md`,
  `app/globals.css`).
- Postgres on Neon through Drizzle. **Schema changes go through Drizzle
  migrations; no hand-edited SQL**, applied with `pnpm db:apply`.
- **Deployed on NETLIFY.** Not Vercel. The build is the literal command in
  `netlify.toml`.
- **The scheduler is GitHub Actions, not platform cron.** Counts and cadence are
  asserted in `tests/push-main.test.ts` and `tests/refresh-cadence.test.ts` —
  read them rather than a number written here.
- Auth via Auth.js, email magic link only. No OAuth, no social login.
- MapLibre GL with a vector tile provider. Not Google Maps.
- Mobile is responsive web first.

## Repo layout

**The tree is the tree; read it.** `docs/code-manifest.md` is authoritative. The
placement rules that are decisions rather than descriptions:

- **`lib/sources/<name>/`** — one ingestion adapter per external source, each
  exporting `fetch()`, `normalize()`, `upsert()`. **Adding a source means adding
  a directory, never editing shared ingestion logic.**
- **`lib/db/`** — the Drizzle schema, migrations and queries.
- **`lib/governance/`** — the governance schema, ledger, compiler and validator.
- **`lib/workstate/`** — canonical multi-session work state.
- **`lib/method/`** — cumulative project discovery knowledge.
- **`tests/fixtures/`** — recorded API responses. **No live calls in tests.**
- **`docs/`** — methodology, policy and the standing record.
