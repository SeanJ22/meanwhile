# BL-02 address comparison sources

Ten real addresses were entered into TurboVote's public address-search form, then its View Sample Ballot page. No account was created and no voter choices were selected. Each saved HTML gzip is the entire rendered source DOM; its capture JSON records the SHA-256 of the uncompressed HTML, URL, candidates and office identifiers. Collapsed office contents were parsed too. Ballot measures are `li[id^="bm_"]`, not office `details`; their titles and summaries were replayed from the saved HTML.

Google Civic's live election catalog selected election 12000 for November 3, 2026. The ten voterinfo calls use the provided key; no credential or key-bearing URL is retained. Eight HTTP200 responses provide no contests. This is missing comparator data, not an assertion that no races exist.

The report at `data/ballot/reports/bl02-address-gaps.json` compares these sources with current held state inputs. `ballotForDivisions` receives the actual basic OCD IDs returned by TurboVote. This does not replace the production page's point-boundary reader proof. File hashes identify which held inputs were compared. Do not create whole-county memberships from these samples: Board of Education, BART, regents, wards and council districts can split a county or city.

Follow-up workers must confirm source-listed missing contests against the responsible official election office and its electorate before publishing. TurboVote has local mapping limits: its Detroit City Hall sample includes suburban library districts, and its Austin Capitol sample includes North Austin MUD1. Its Austin basic geocoder returns CD37 while its November ballot returns CD10. Google's Salt Lake City sample includes sixteen unnamed judicial contests, one labelled Alta. These contradictions remain explicit in the gap list.

Acquisition used the inherited HTTPS proxy and configured CA. The browser's requests were fulfilled from Node HTTPS responses with TLS validation enabled, scoped to this run. Analytics were blocked. No persistent certificate trust was changed. The pinned Chromium1234 was installed in `/tmp/bl02-playwright` for the run.

The exact-address reader proof is now saved separately from the ZIP proof in `data/ballot/reports/bl02-page-replay-exact.json`, with a tomorrow render. San Francisco's public Enterprise Addressing System three-column CSV was downloaded in full without sending the requested address to any geocoder; exact local equality uniquely matched `120 LAKE ST`. The full compressed source, hash and matching row are retained here. The actual page receives only the matched latitude/longitude and state, without a ZIP. Its ordinary point resolver uses the saved official BART polygon plus the eight saved official SF CCD polygons; the county ancestor activates the sourced BOE2 membership. Both requested cards were inspected in the exact-point screenshots. The first exact-point failure exposed the missing county geometry, and the ordinary geography data was repaired; no runtime code changed.
