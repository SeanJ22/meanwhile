# acs5_2024_b01003_zcta.csv — source note

## Source
- **Agency:** U.S. Census Bureau, American Community Survey (ACS).
- **Dataset:** ACS 5-Year Detailed Tables, 2024 vintage — identifier `https://api.census.gov/data/id/ACSDT5Y2024`.
- **Variables:** `B01003_001E` — Total Population, estimate; `B01003_001M` — its margin of error at 90% confidence.
- **Geography:** every ZIP Code Tabulation Area (ZCTA5) the release tabulates. This is a ZCTA population and nothing else — not a city or town estimate, not a county figure, and not a Population Estimates Program value (§9A.19).
- **Request (key redacted):** `https://api.census.gov/data/2024/acs/acs5?get=NAME,B01003_001E,B01003_001M&for=zip%20code%20tabulation%20area:*&key=<CENSUS_API_KEY>`
- **Documentation:** https://www.census.gov/developer/ · terms of service https://www.census.gov/data/developers/about/terms-of-service.html
- **License:** a work of the United States federal government — public domain. The API's terms ask that a key be used and the Bureau be cited; both are done.

## Why the 2024 vintage
- ACS 5-Year is released one vintage at a time, and the newest is the only honest one to render. Measured directly on 2026-09-06 with this repository's key: `/data/2024/acs/acs5` answers HTTP 200 and `/data/2025/acs/acs5` answers HTTP 404. 2024 is therefore the newest 5-Year release published for this geography.
- The previous table on file was the 2023 vintage (`acs5_2023_b01003_zcta.csv`, acquired 2026-09-05). It is superseded and removed; the dataset id carries the vintage so the two can never be confused.
- There is no Population Estimates Program product for a ZCTA. Where a newer Census estimate exists only for a different geography (a place, a county), it is NOT substituted — that would be a different measure wearing this one's label.

## Acquisition
- Acquired by `pnpm acs:population` (`scripts/acs-population-refresh.mts` over `lib/sources/census-acs-population`) on 2026-09-06, from this repository, with the repository's own `CENSUS_API_KEY`.
- HTTP 200; 33,772 data rows returned after the header row; 33,772 written — the same delineation the 2023 release used. The row count is pinned in `lib/reference/index.ts` and checked by `tests/reference-data.test.ts`.
- Independently verified before the table was committed, by a separate live call on the same day: ZCTA 85633 = 48 (± 29), 85654 = 0 (± 14), 85701 = 5,498 (± 734), 03255 = 2,015 (± 229).
- Columns: `zcta` (five digits), `name` (the API's `NAME`, e.g. `ZCTA5 85701`), `population` (an integer estimate, never blank), `margin_of_error` (the Bureau's 90% margin, or **empty**).

## The margin of error, and why it is carried
- An ACS 5-year figure for a very small area is an ESTIMATE with an interval around it, not a count. Rendering `0 people` or `32 people` as a bare fact — which is what the owner saw on 2026-09-06 — states more than the Bureau does.
- `B01003_001M` is the Bureau's own published margin at 90% confidence. `lib/reference/acs-population.ts` classifies each estimate against it: an estimate of 0 reads **recorded as none**, an estimate its margin reaches reads **within the margin of error**, and anything else is a count rendered with its `±`. The dividing line is the Bureau's interval, never a threshold invented here.
- 598 of the 33,772 rows carry an estimate of 0; a further 961 carry a non-zero estimate no larger than its own margin.
- **An empty `margin_of_error` cell means the Bureau published a jam value, not a margin of zero.** The API answers `-555555555` ("the estimate is controlled; a statistical test is not appropriate") and siblings where no margin applies; every jam value is negative and a margin cannot be, so the sign is the whole test. 13 ZCTA rows are jammed this way (verified live: ZCTA 00627 returns `-555555555`).

## What a ZCTA is, and is not
- A ZCTA is the Census Bureau's generalisation of a USPS ZIP code, built from census blocks. Most residential ZIPs map to a ZCTA of the same five digits.
- A post-office-box ZIP, a single-building ZIP, or a ZIP created after the release has **no ZCTA row**. Downstream that is a NAMED GAP ("no Census tabulation area for this ZIP"), never a population of zero (RULING 159).
- A ZCTA's boundary is not a town's boundary. The place NAME beside a ZIP on the readiness panel comes from a different join entirely (`data/derived/zip-division-ids.json`), and the two must not be read as one geography.
- The estimate is a 5-year average (2020–2024), which is the only ACS product published for ZCTAs.
