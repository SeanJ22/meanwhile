# Admin v6 instruction history

Control-plane schema v16 installs the action-history companion tables and indexes through `lib/control-plane/repository/pg-schema.ts`, outside serving Drizzle migrations. Version 17 replaces the receipt-companion refusal with history invalidation, so older providers can still save receipts before the new writer lands. Their receipts remain unprojected; no scope or action mapping is invented. The [current SQL definition](migration-proposals/admin-action-history-cp-v17.sql) retains deferred projection/scope parity and immutable-source guards. The Postgres provider routes new `admin-action` receipts through `appendActionReceiptWithHistoryAtomic`: one parameterized statement allocates the log position and writes the canonical receipt, companion, scope reference and readiness invalidation together. It applies to refusals as well as accepted actions. An ambiguous transport result gets one readback, without resubmitting the action.

The existing gateway receipt remains authoritative. Its immutable companion retains the original receipt ID, type, idempotency key, canonical append position, timestamp and source hash. The current mapping recognizes global runner pause/resume commands. Other commands retain an explicit unavailable mapping; their subject or human-readable prose does not establish a geography, instruction identity or new-hunt meaning. Identical append replays preserve the original timestamp and position.

Historical receipts remain unbackfilled. The Admin history adapter exposes global runner controls, keeps `page.total` unknown and names missing scoped coverage. No readiness watermark is asserted, and history remains unannounced by live pulse. Scoped history requires durable canonical place and instruction membership from validated commands before it can claim complete coverage. Sharing a geography does not make two instruction receipts the same hunt.

The v16 provider also installs the active-claims lease lookup and latest-cycle version indexes. The bounded readers use these indexes and report unavailable evidence explicitly. Staging validation exercises the provider; production application waits for Sean to resume the runner.
