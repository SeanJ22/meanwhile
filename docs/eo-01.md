# EO-01: local election offices

## Connection and delivery

**Upstream: NX-PLACE and DS-01.** The normal address/Census and ZIP geography paths identify the county or municipality; production's canonical state registration pointers supply its identity. State election-authority directories establish the offices, and local offices' own election pages supply additional fields.

**Downstream: LV-01 and the VS-01 voting panel.** `lib/reference/local-election-offices.ts` reads one state's promoted office projection and selects the county or town. `components/map/local-election-office.tsx` provides the contact and per-field Sources contribution. The zero-site answer must include this contact before the state office once `READY: LV-01` appears in `origin/river`. That dependency has not appeared. The helper is not yet wired into the page. No code in `lib/sources/google-civic/` was changed. No existing reader code has been replaced yet.

The source uses the existing candidate, evidence-vault, promotion, reader and Door Registry paths. It adds 51 state/DC contracts, editable state route indexes, weekly refresh through November 3, 2026 in America/Phoenix and monthly refresh afterward. Failed pages retain independently verified facts and their original check dates; field gaps remain OPEN work. Mailing boxes do not become street addresses, and polling hours do not become office hours.

The Missouri state directory and KCEB's own page explicitly divide Kansas City within Jackson County from the remainder of Jackson County. Held scope restrictions and municipal exclusions preserve that boundary even if one office is unavailable. The source-authority helper now recognizes explicit website links in native published JSON directories as well as HTML links; unrelated text containing a URL does not establish a government link.

Production publication was attempted through `scripts/local-election-offices-import.mts`. It stopped before any mutation with `The shared raw-capture evidence vault is unavailable.` This environment lacks the production vault configuration and sanctioned publication handles. The Netlify connector exposes masked configuration rather than the required credential values. The acquired offices and routes are preserved locally; they have **not** been published to production or installed as production doors. Code has not merged or deployed.
