# Reader last-mile census method

The census starts with `lib/holdings/datasets.ts`, the current canonical state holdings manifest inputs, and the committed autonomous lifecycle readback. It counts typed records rather than JSON files. A meeting, its extracted agenda, a source roster, its projected officials, and a source image are separate units; their counts must not be added and called people or meetings.

The frozen baseline is `reader-last-mile-baseline.json.gz`. Its original UTF-8 JSON SHA-256 is `190a355f997bda81976d9bb3d7c472b386f82920a1a79e68f850bee14a156348`. The adjacent `.pack.json` records both the original and compressed byte hashes. Gzip has a zero modification time and round-trips to the original bytes. Packaging did not rewrite the baseline or turn its unmeasured counts into zeroes.

## Separate proof boundaries

1. `buildReaderCensus` parses holdings, applies the existing reader contracts and inventories every declared family/surface/state edge. Its default is `DELIVERY_UNPROVEN`, with null false-negative and false-positive counts. An import does not assert a reader render.
2. `projectCanonicalReaderRecords` executes a reviewed canonical selector for every applicable direct record. It records the selected payload hash, returned identities/count, and the selector. Missing direct records fail. Acquisition records, superseded extractions, unresolved finance leads and autonomous staging remain withheld.
3. `applyReaderApplicability` retains the full held-eligible population while identifying supporting source inputs and records outside current scope. Each exclusion carries its executed selector and specific reason. Direct current answers remain obligations. This operation never marks an answer `RENDERED`.
4. `renderCanonicalReaderComponents` executes the actual product React components against every payload in each supported leaf class. The evidence contains the full emitted HTML, its hash, canonical identities from the selected payload, the component's source hash, expected and forbidden civic fragments, and actual row counts. It includes wrong-body and ineligible-money negatives. The evidence proves component output; deployed routes and an in-situ browser walk remain separate requirements.
5. `reconcileDelivery` checks supplied executed route/browser evidence against the census. It verifies the artifact hash, exact head format, canonical identities, expected/actual record sets and stated/returned counts. A sample cannot discharge the rest of a row. Bundle evidence must name the same head and cover the holdings. `censusClosureFailures` remains nonempty until every applicable direct edge has those proofs.
6. Independent measured subsets can combine only at the same exact head. Their original evidence paths and observed expected/returned audit IDs remain on the census row. A successful component render additionally needs a hashed, same-head in-situ witness for the actual component on that declared surface. An API proof cannot impersonate a visual component render.
7. Bundle evidence distinguishes actual NFT filesystem copies, statically imported inputs compiled into the reader, and public portraits fetched over HTTP with matching vault bytes. Staged/support-only siblings are not deployment requirements for a directly measured record. No proof means deployment remains unproved, even when a route handler or component succeeds locally.

## Repeatable commands

Run from the repository root with Node 24:

```text
node --experimental-strip-types --import ./scripts/register-test-loader.mjs scripts/reader-last-mile-census.mts --project --projection-closure --render-components
node --experimental-strip-types --import ./scripts/register-test-loader.mjs --test tests/reader-last-mile-census.test.ts tests/reader-last-mile-trace.test.ts
```

The JSX proof loader compiles actual product TSX in memory with the repository's TypeScript compiler. It does not substitute a test component or change runtime reader imports. The census script uses the canonical denominator floor and fails rather than reporting an empty successful population.

To reconcile a previously executed projection and reader proofs:

```text
node --experimental-strip-types --import ./scripts/register-test-loader.mjs scripts/reader-last-mile-census.mts --projection docs/evidence/reader-last-mile-current-projection.json.gz --proof docs/evidence/reader-last-mile-delivery-proofs.json.gz --closure --authority-evidence docs/evidence/reader-last-mile-rehearsal-authority.json
```

`--executed-proofs path1.json,path2.json` reads the actual route/browser instruments and correlates their native IDs to canonical audit records. `--components path1.json.gz,path2.json` composes actual HTML cases with `--component-witnesses` and `--bundle-proof`. Without a bundle descriptor, executed route composition reports only the observed delivery and cannot pass closure. `--build-receipt` plus `--portrait-proof` generates the checked bundle evidence and its descriptor from a completed exact-head production build.

Every new fresh closure also requires a hash-bound execution-authority artifact. It labels the run `REHEARSAL` (an isolated production clone) or `PRODUCTION` (the standing production store), binds the one exact proved code head, sanitized Neon project/branch/endpoint/database/schema identities, the separately identified read-only role and refused-write proof, the importer code/receipt, and the exact canonical pointer-set hash/count. Ordinary certification accepts either honest phase; `pnpm reader:production-closure` is the separate post-evidence terminal gate and accepts only `PRODUCTION` whose endpoint, database, schema and read-only role hashes match the active `WTP_PRODUCTION_DATABASE_URL_READONLY` handle. A rehearsal receipt therefore remains useful pre-production evidence but cannot be relabeled into terminal proof.

`--pack docs/evidence/reader-last-mile-current.json` losslessly packages one generated JSON artifact. `readReaderEvidence` and the script accept packed evidence; `--check` also reads a packed output if its plain JSON was removed. Baseline creation refuses an existing plain or packed baseline.

The final execution used mixed CRLF/LF working bytes in exactly two source files: `app/api/ask/grounded/route.ts` and `scripts/lib/reader-ask-ballot-proof.ts`. Git had already committed their LF forms under the repository's `eol=lf` rule. The receipt preserves the original executed bytes in compressed source archives, their original hashes, the exact CRLF-only conversion hashes, and the original proved head. TypeScript 5.9.3 emitted identical JavaScript from each pair with LF output, source maps disabled and diagnostics checked. Only after those proofs passed were the working files restored to their exact existing committed bytes. This is a receipt-only, two-file equivalence: other source hashes remain strict, a changed code character fails, forged archives fail, and arbitrary whitespace or source normalization is not accepted. The full repository build and gates use the committed LF sources. Recorded civic responses, raw source facts and screenshot hashes were not changed.
