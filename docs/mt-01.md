## Release 97 production follow-up

At 11:50 AM Eastern on October 24 (15:50 UTC), the sequential Chrome walk on meanwhileusa.com failed at Raleigh before the list could load: `/api/meetings?zip=27601&include=state` returned HTTP 502. The first failure, screenshot, and console errors were retained. The remaining walk was paused. A subsequent diagnostic request succeeded at Raleigh, while Milwaukee still returned 502; recovery alone was not counted as a pass.

Netlify's production function logs identify the cause: `unsupported startup parameter in options: jit`, PostgreSQL code `08P01`. Release 97 added `-c jit=off` to `lib/reader/database.ts`'s pooled connection startup options. Neon rejects that setting in the pooled startup packet. The focused fix removes that option and keeps the existing read-only startup setting. No remote database setting or data was changed.

A direct paired connection probe against the supplied production reader branch and `readonly` role reproduces `08P01` with the release 97 options. The corrected options return `current_user = readonly` and `transaction_read_only = on`. The four existing reader connection/deadline tests pass. The pinning implementation, two production-data publication proofs, 50-state paired counts, and controlled following-publication proof above remain applicable. The 20-ZIP production Chrome walk and first actual post-deployment publication still need to pass after this repair ships.
