## Changed reads

- Platform discovery and seed-time duplicate retirement: complete door rows -> OPEN/SHUT matching fields only. All status, family, crosswalk, same-body, normalized tenant/name and agenda-system rules remain. Retirement fetches only the full duplicate it must change, rechecks that it is still a census door, and uses its revision. It preserves the complete stored config. Empty discovery does no listing. The last server-side hand-wired predicate is blocked by the protected repository file; see below.
- Manual saves: full entry payloads before every save -> merge metadata plus the METHOD and PARSE_FIELDS union fields. A newer observation supplies its own payload. Stale observations, uncertain no-ops and lost CAS races load the complete current entry. Replayed identical inputs compare the database revision against a bounded set of input hashes; page bodies are never cached. Canonical JSON comparison avoids rewriting equal JSONB merely because its keys came back in another order.
- Normal worker and research vault lookup: complete artifact log -> keys and rows matching the requested artifact, through one shared metadata reader. Log order, complete-capture selection, provenance and errors remain. An explicitly frozen publication pass retains its existing one-time snapshot semantics.
- Method spread: complete door table including captures -> OPEN door identity, place, hosts, kind and only the URL config keys the existing probe reads. The same plans and free tries result.
- Own-site resume: complete manual entry -> only website and the saved frontier/read queues it consumes.
- Method-version reads: complete route payloads -> route IDs, source and base version. Method-knowledge reads compare current route-row revisions, loading only new or changed rows. Callers get an isolated copy. Worker catalog requests use the existing authenticated shared-tools host, which now owns the revision-checked cache. An unchanged worker request loads no full route rows; changing a route reloads only that row. Unseeded and unavailable-store errors retain their messages.
- Mission refresh: full door-table reads -> selectors for mission marking and only marked-door selectors for settlement. Full values are loaded only for records that need changing, with the original CAS revision. Unrelated stored captures and adapter config remain intact.
- Artifact history for one attempt: all of a work item's artifacts -> the records for that attempt only, in their original order.
- Owner snapshot folding: complete state snapshot -> builtAt, allRowsIndex and bodyAttempts. Spend is rebuilt from the existing place totals; its redundant previous display rows stay in the database.

The other owner totals/history callers already read particular state rows, work-item IDs or changed rows, with projections and held revisions. Scheduler transition reads need the current single aggregate for their CAS. Scout/campaign reads already constrain subject or candidate. Voting-source registration reads a particular URL or state; merging its full mappings/config and preserving duplicate updates is required.

## Pieces blocked by files owned by other lanes

1. `lib/control-plane/repository/pg-store.ts`: expose a narrow hand-wired door lookup to replace the remaining active-door descriptor scan. Use ID pagination/order and project only the matching fields. The exact JSONB predicates are: meeting exists and is not JSON null; `coalesce(value #> '{meeting,family}', 'null'::jsonb) = 'null'::jsonb`; `NOT (value->'config' ? 'crosswalkRowId')`; and status OPEN or SHUT. JSON null in crosswalkRowId still counts as census, matching JavaScript's undefined check. For retirement, expose census descriptors with the inverse crosswalk-existence predicate, then fetch only confirmed duplicates for CAS. No origin=MANUAL shortcut: seeded hand-wired doors can be DERIVED. This file is untouched.
2. `lib/control-plane/box.ts` line 128 and its repository implementation: each indexed/replayed finding rereads the full growing origins/attempts row just to detect an existing origin or add one. Add a repository operation that compares the supplied canonical/legacy IDs and origin identity inside SQL, returning only the revision/change result and applying the origin/reference merge under the current CAS. Preserve existing fact identity, legacy fallback, source references, lastRecordedAt, builder state, claims, attempts and generation. This is the 4.99 GB/day caller and is untouched.
3. `pg-store.ts` plus `scripts/freshness-shadow.mts` candidate snapshot: `methodCandidates.read('live')` downloads every complete candidate each round (0.318 GB/day across its two line labels). The consumers need counts plus each candidate's id, lifecycle, submittedAt and admission, not full proposals, validation evidence or rejection history. A SQL projection must narrow each array member; the existing projection API keeps arrays whole. This cannot be fixed by a caller projection alone. Both locations are left as they were for this piece. The aggregate put path also rereads its entire newly inserted row: return id/revision/updated_at from the insert and reuse the submitted value on success, retaining the read on an identity conflict.
4. `scripts/routine-civic-data-runner.mts` repeatedly calls `listDoors` for publication, read-now and derive-due work. Replace those calls with their individual status/readNow/partition projections and pass shared results through each unchanged pass. `recordProbe`, door upserts and Box updates require full rows for the current whole-value CAS API; a repository field-update operation would avoid returning the stored capture/config just to change health fields. The protected runner and repository files are untouched.
5. Artifact append-conflict recovery in `recordArtifactMetadata` reads all artifacts for the work item because it must return the original log position. A repository point read returning the matching record and its actual position would remove that repeated history transfer. Filtering in application code cannot preserve the original position. Its repository integration is blocked by `pg-store.ts`.
