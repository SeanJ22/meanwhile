# PK-01: picks across devices

A reader can save the list in My picks, keep its private link, and open it on another device. Both devices then follow the same list. No contact information is collected.

The lane was cut from `origin/river` at `78f82a232`. `app/ballot/page.tsx` and `docs/rulings.md` are unchanged.

## Connections

- **Feeds PK-01:** BA-01's published ballot contests and candidate choices, already passed to `MyPicks` and `PickControl` by the ballot page.
- **PK-01 feeds:** BL-01's existing ballot controls and My picks summary through the existing picks subscription. Restoring and syncing publish that subscription without creating reader events.
- **Business branch:** the existing anonymous `BALLOT_PICK` intake → immutable `reader-event-history` batches → `candidate-pick-totals` recipe → the existing Admin capture API and panel. It uses the ordinary recipe/audience switches. Reader pages consume no candidate totals.

## Storage and behavior

`saved_ballot_picks` holds only a domain-separated digest of a random 256-bit secret, the picks file and a revision. It has no reader identifier, contact, IP, ZIP, timestamp or event-store join. The capability travels in the link fragment, then in an authorization header. The fragment is removed from the address bar on opening; responses are private and uncached.

The browser retains its existing picks cache and a durable outbox. Updates compare the server revision and rebase only edited contests. Visible pages check every 30 seconds, and on focus, visibility change and online. Hidden pages have no polling timer and make no sync requests, including when first opening a saved link. Reader edits send immediately; edits made during an in-flight check drain as soon as that check finishes. Clears, unsure marks, suppression and multi-seat choices travel with the list. Save materializes currently derived choices using their existing choice IDs. Names are valid choice IDs on general-election lineups and must survive intact. Visible link reads start during hydration to avoid an extra round trip after the page is ready.

Each existing tap still emits exactly its existing anonymous pick event. Save, restore and polling emit none. ZIP and contest division now accompany those same events. Candidate totals count recorded selection events, including later selections; they do not claim to be a current vote count. Blank, unsure, measure Yes/No and synthetic events contribute no candidate selection. Historical missing geography remains unknown.

`PK-01_saved_picks.sql` is an expand migration, registered in the journal and phase declarations. River numbers it. It was exercised in PGlite and applied only to the approved development branch; the production build applies the numbered migration before serving the endpoint.
