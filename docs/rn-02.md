# RN-02 — calendar delivery and reader repair

Implementation revision: `1f901339b`, based on `origin/river` at `78f82a232dd1d0545a46835e7716032ff3807425`. Focused checks and both national replays are complete. The READY commit adds this report and its evidence to the validated implementation.

A resident should receive the next meeting of their board when its source has been read, regardless of state. CAL-01 feeds this work through the door registry (`cp_doors`); RN-01 supplies standing-frontier admission and exact calendar assignments. RN-02 publishes the registry list, admits the state programs, retains native source receipts, and verifies the typed Reader. Its output feeds RN-01's standing frontier and hot-read catch-up, then PM-01's native facts and `/api/meetings` and the page's **Who governs here? → Next meeting** card. `lib/civic-data/runner.ts` is unchanged.

## Changes

- Only an exact, hash-bound SUSPENDED registry record authorizes removal from `meeting-doors`. All open doors, including derived-family doors, remain in the publication. Candidate envelopes reference shared content-addressed payload parts, so repeated refusals do not store full copies.
- Calendar children receive the parent's exact partition contracts and use that selection to install wiring and hosts. They cannot independently replace it with a different registry snapshot. Derived readback identities use their registered derived source.
- Reader repairs inspect identities and latest receipts in batches, reuse exact current evidence, and read two stale typed projections together. Unrelated repairs start alongside sources; repairs of a source and its dependent candidacy registry join wait for that source. PDF extraction uses the runner's installed Poppler process, and canonical pointer proofs stream their hashes instead of cloning whole payloads and materializing two large JSON strings.
- Fifty registry doors with corrected body identities remain connected to their exact current body/source/route. Read-now requests use the current task, and success/failure clocks return to the stable registry door. A stale-body read cannot credit its corrected successor; ambiguous matches refuse. A production read-only replay resolves all 50 (CA 43, FL 7), using 100 narrow requests and 179,157 response bytes. The in-memory repository now matches PostgreSQL scalar JSON paths through array indexes.
- Measured peaks survive service restarts in `/var/lib/meanwhile/meanwhile-worker-memory.json`; every running sample is persisted. Tenant, readback and ZIP jobs pool observations by family. The ZIP reservation precedes the state-publication fallback and stays at least 1,229 MiB. A restarted measured 170 MiB Legistar family reserves 179 MiB for a new tenant. The tests include a real process exiting without release, followed by a separate process recovering its saved sample.
- Identical failed inputs get a new immutable attempt and exact receipt, rather than an illegal terminal-state recheck. Native Legistar failures and missing PRL archive configuration produce durable failure receipts. Same-state candidacy joins have narrowly scoped registry authority. Google Civic timestamps and LegiScan failure URLs bind receipts to the actual source evidence.
- Agenda downloads retain one upstream request per URL but spool exact bytes to SQLite’s anonymous TEMP file with an 8 MiB page cache, rather than holding every PDF in RAM. Meeting candidates use bounded content-addressed parts; a historical board previously generated a 143 MB request and exceeded Neon’s 64 MiB request limit. The source preflight and normalized hash now stream too. Replaced payload-cloning, failed-recheck, eager-fetch, RAM-byte-cache and PDF extraction paths are deleted.

There are 90 native children after bulk inventory checks, rather than 163. The cold replay’s largest sampled child peak is 1,003,159,552 bytes, below the retained 1,046 MiB floor.

Starting separate children for missing publications wasted the pass budget. The fix checks canonical pointer identities in the supervisor after the relevant source phase. Proven NO_PROMOTION results finish there; existing, unread or contradictory inventories keep their exact contracts for typed child checks. A later promotion is picked up on the next inventory, and a failed query never becomes absence. The original snapshot resolves 6,129 unpublished contracts this way. A final registry check found 46 additional doors: the expanded 6,958-contract replay resolves 6,175 unpublished contracts and still requires 90 native children. Both expanded passes finish in 249,715 ms (4m 10s) and 254,493 ms (4m 14s), with 782 CURRENT PASS, one NH source-proof FAIL, zero protocol failures and zero deferred children. The fresh door replay promotes all 5,862 open doors, and all 5,908 meeting contracts map to exactly one state.

These measurements were made in this execution environment against production-data copies, not by SSH on the production runner. No production-runner SSH credential is available here. The live 8 GiB runner remains an explicit post-shipping check.

Choosing one would invent an identity decision. Calendar source receipts and reader checks succeed independently. The registration identity owner must correct that collision.

**Live upstream admission:** the pre-shipping production baseline captured from passes at 8:27, 8:31 and 8:35 AM ET on October 23, running `825ff1c43ff44632923f1011e9480b961aa20dbb`, attempt zero sources. Each records `HUNT_SCOPE_UNREAD`: reading `cp_work_items_history` exceeds the 30,000 ms Neon request deadline during headers. RN-01 owns that upstream admission path. A read-only production door check still finds no recorded success outside AZ/NH/NJ. Live CA/TX APIs still return zero meetings before shipping. None of these baseline failures is reported as fixed by a copy replay.
