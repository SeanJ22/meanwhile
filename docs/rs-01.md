# RS-01: state and place reader packages

RS-01 is being verified on `stream/rs-01`. It has not been marked READY, merged or deployed. The browser checks and the current President's production publication remain open.

Servers share one resident national shelf containing the held congressional roster, offices and ZIP-to-place table. ZIP lookup identifies the state without a database read. Each state has its own ZIP index, including cross-state and postal aliases. The reader starts one whole-state request and one indexed local/county fact-store request together. State information publishes first; the state request includes office directories for subsequent contact cards. Boundaries use vector tiles, so the map requests only the geometry it draws. Successful resident data refreshes against canonical promotions every thirty seconds, retaining its last verified value if a refresh fails.

Typed and restored ZIPs use the small location endpoint instead of downloading national ZIP tables into the browser. GPS and explicit nearest-location actions retain their on-demand tables. Static HTML does not await the national module import. Ballot prefetch waits for the requested place's data, keeping its extra reads out of the initial ZIP load. Reader receipts retain publication checks and exclusion reasons without transferring rejected-record copies; the original canonical audit receipts remain intact. Geography metadata travels once per scope rather than once per district.

The runner no longer packs reader copies. Reader manifests, authority copies, body copies and the merged national meetings document have been removed from the reader and publication paths. Step-named migrations retire the obsolete tables and pointers while retaining source candidates, versions, evidence and history. They have been checked in PGlite, not applied to production during this work.

## Measurements so far

The slowest usable response captured before this change took **9.25 seconds**, in Tucson. Its old backend spent **3.68 seconds** in coverage alone. Only three complete baseline responses were captured: Tucson, New Jersey and Rhode Island. The other forty-seven returned incomplete responses and are not completeness evidence.

The latest fifty-state direct-handler check passed all **150 cold, repeat and next-ZIP data reads** against production with a verified read-only role. Its slowest cold data result was **2.05 seconds**, Tucson; repeat was **0.76 seconds**, Tucson; next ZIP was **0.57 seconds**, Illinois. These timings include response parsing and coverage merging but exclude module imports, network transfer to a browser and browser rendering. Including imports, the slowest cold result was **3.58 seconds**, Indiana; Tucson and Idaho also exceeded three seconds. These data checks do not establish complete browser acceptance. Compact current measurements and preserved failures are in [rs-01-results.json](rs-01-results.json).

The latest full built-browser run passed all checks in **49 of 50 states**. Indiana still took **5.71 seconds**, with no CPU throttling during that navigation. New Jersey was next at **2.89 seconds**. Tucson showed state information in **2.02 seconds** and its complete held local information in **2.27 seconds**. Every state's rendered counts matched its held package, and this run recorded no HTTP or premature Ballot-prefetch errors. Indiana remains a failed cold load; the three-second requirement is still open.

Earlier failures remain in the evidence. The first full browser run exceeded three seconds in six states, with New Hampshire slowest at **4.14 seconds**, and also exposed source-native contact-ID errors. The preserved prefetch run exceeded three seconds in Georgia (**3.91 seconds**), New Hampshire (**3.26 seconds**) and Ohio (**3.23 seconds**); Michigan's data arrived in **1.93 seconds** but its external public settings GET returned a 503. The previous CPU-isolated full run failed Florida at **3.30 seconds**. A later fast diagnostic visit does not replace any of these failures.

The host allows four CPU cores of work across five available CPU IDs. A controlled Georgia experiment used three fresh server/browser pairs sharing those CPUs and three pairs with the server pinned to CPUs 0–1 and Chromium to CPUs 2–3. The worst loads were **3.41 seconds** shared and **2.66 seconds** separated. The separated allocation was then kept for both full-state runs; every state still used a fresh server and browser, the same three-second limit and no reader-API retries. Florida's earlier miss recorded only 0.47 milliseconds of throttling, and Indiana's current miss recorded none. CPU allocation alone has not resolved the remaining failure.

An instrumented Indiana diagnostic measured a 221-millisecond first state-route import, a 352-millisecond event-loop stall and 461 milliseconds of blocking during national startup. It completed in 2.44 seconds and did not reproduce the original failure. These measurements confirm synchronous initialization queues other requests; they do not explain the full two-second startup anomaly. RS-01 still owns that investigation before READY.

On the actual built entry page, typing **85701** showed its complete held information in **2.99 seconds**. The House member's contact card, both senators' cards and a reopened House card took **0.62, 0.32, 0.24 and 0.28 seconds**, with no recorded errors. The cards showed Grijalva's held Tucson office and both of Kelly's and Gallego's held offices, with addresses and phone numbers. An earlier phone-viewport check took at most **1.13 seconds** per open. These built-page checks used public production GETs for Netlify-only portraits, settings, link health and boundary tiles and blocked application writes and beacons. The local environment has no basemap key, so the separate map background was unavailable; no production key was copied for synthetic testing.

## Completeness

Tucson retains its 243 meetings, 65 bodies, three district seats, seven divisions, sixty distinct official identities and two state-office records, including the held contact, campaign, social, term, calendar-link and address fields. Grijalva has one held office; Kelly and Gallego each have two. New Jersey's 22 meetings and Rhode Island's two government listings also remain present in their captured baseline ZIPs.

A broader comparison against every old copied meeting found a state-family scope mismatch. Correcting the canonical `US-<state>` key recovered the derived calendars and their venue-gap fields. All copied IDs and checked fields in the current ninety-day shown window now survive across 175 bodies. Historical reads also recover the three older New Hampshire calendar entries from retained, verified source versions. The audit preserves all 1,271 copied IDs, twenty cancellation states and checked source fields. Sixty-eight source-only bodies now reach the existing body-card path from their published calendar names; no service territory is invented for a body lacking an association. Compact evidence is in [rs-01-preservation.json](rs-01-preservation.json).

The production national shelf contains 539 distinct current congressional records across 56 jurisdictions and 41,831 ZIP aliases. Four records have no held district-office record. Production has no verified current President record. The change includes a standing White House source that follows the current administration index, verifies the own profile against saved source evidence, publishes through the existing source flow and retains former holders. Publishing that missing record through the standing acquisition flow remains open; the read-only production checks do not fabricate or publish a holder.

Recorded production-build, TypeScript, lint, reader-trace and bundle checks pass; they do not clear the browser-speed or missing-President blockers. The largest application trace contains 428 files against its unchanged 430-file ceiling; initial client JavaScript is 314.5 KB compressed. A combined regression run passed 486 tests across 74 files with none skipped. Later focused checks cover ZIP entry and retries, all 56 state ZIP indexes, exact geography preservation and Ballot navigation. No stylesheet changed.
