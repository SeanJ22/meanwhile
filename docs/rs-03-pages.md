## Causes and changes

- The map delayed fitting meeting venues by 2,800 ms even after its initial ZIP jump had finished. It now fits the initial result immediately and uses the actual movement-complete event for later flights. Repeated equal bounds do not move the camera again.
- The ZIP state route indexed the entire static ZIP directory although it already held the requested ZIP. It now uses that entry and passes the ZIP to the existing Census metadata reader.
- Browser ZIP restoration also waited for a server function to load the national postal tables. The build now projects the same held coordinates and postal metadata into 100 regional CDN files. All 42,446 placeable ZIPs match the original lookup, including mail-only aliases. No place facts are invented or dropped. These browser files are excluded from function traces.
- Office pins issued separate directory requests for representatives whose sourced offices had already been read in the state response. The compact ZIP response now carries only its selected people's offices, provenance and held empty directories. Exact identity and ambiguity checks remain in place.
- Control remounts fetched settings again and restarted the minute clock. The page now shares one settings read and one refresh clock, retaining minute and focus updates. Settings and state outlines start with the arriving ZIP data and are consumed once.
- An enabled first Ask press could arrive before its place context, and focus could run before the lazy input mounted. Ask becomes enabled with its context, and each actual input focuses when it mounts. The Admin speed runner also presses the real button instead of dispatching an event before hydration.
- Software graphics compiled the complete vector basemap locally and painted four canvas pixels per CSS pixel at DPR 2. Positively identified software renderers start with MapTiler's published raster TileJSON for the same theme at DPR 1; the provider supplies the tiles, zoom limits and attribution. District boundaries, labels, selection and pins retain their existing interactive layers. Hardware and unknown renderers retain the vector basemap. Reduced-motion visits also disable the initial symbol fade.
- Boundary reads and decoding waited for the UI thread. A small worker now owns the existing PMTiles reader. The arriving page starts its bounded header read and, once the ZIP resolves, one center tile at the existing initial zoom. MapLibre consumes that tile once, and all other tiles use the ordinary PMTiles range reader, cancellation and ETag recovery. At most one unused center tile is held. A failed optional prefetch cannot poison the later requested read. No whole archive is downloaded.
- The same worker parses the arriving state response and starts only the selected representatives' missing district-office coordinates, using the existing public-address geocoder and source/identity rules. It runs alongside rendering. The UI shares those pending or recently successful points; the bounded 30-second cache expires and failed matches remain retryable.
- The map engine loads alongside the data without blocking hydration of the ZIP controls. Its first graphics view starts with the complete answer and venue bounds; subsequent ZIP choices keep the existing map. Meetings, officials and the ballot Ask engine load when their controls open.

No shared database client is changed. TX-01 retains ownership of those files. The replacement changes callers and browser startup; it adds no scheduled warming.

## Browser method

`scripts/rs-03-pages-check.mts` uses the existing guarded browser with writes blocked and a synthetic run marker. Each visit has a fresh browser context, empty HTTP storage and a selected ZIP. Local storage starts empty except for the existing Admin speed runner's tutorial-dismissed marker. Phone is 390 × 844 with touch; desktop is 1280 × 800; both use DPR 2. The main comparison follows Admin's reduced-motion profile. Final replacement verification uses ordinary motion. The checker waits for numeric meeting counts, loaded geography, the complete map, the requested panel, the document load event, all initial API reads and two painted frames. Ask and ballot inputs must acquire focus and accept typing on their first press. No question is submitted, no model is called, and no production data or settings are written.

Normal MapTiler access is explicitly enabled and capped at 200 requests per six-visit ZIP/profile run. The pinned Playwright Chromium revision 1234 is installed for the final comparison. Earlier diagnostic runs used an explicitly reported system Chromium substitution and the guarded plain-ground fallback; those results remain recorded and do not establish normal-basemap completion.

Current main is measured on `https://meanwhileusa.com`. The replacement is a Next production build using the existing production `readonly` role. Only the test browser resolves the production host to a streaming HTTP/2 TLS loopback proxy, matching production's protocol and MapTiler's permitted browser origin. Its certificate is local, temporary and removed after the run. Each navigation must carry the local proxy's exact build-ID header. All other readers continue to receive live main. The existing guarded browser blocks writes throughout. The read-only transaction verifies the database role, read-only setting and lack of public-table write privileges. Each built ZIP/profile run starts a fresh server process; the first timed page is its first application HTTP request. The two platform-held GET snapshots, settings and link health, come from their actual live endpoints because local Next has no Netlify Blobs context; their wait remains included in the page timing. Built measurements include browser rendering and production data, but do not measure Netlify deployment startup or CDN hits.

The loopback proxy serves the build's immutable static bytes directly, precompressed as CDN assets. Documents and APIs still reach the fresh Next process. Routing every static asset through the local function server introduced a cold delay absent from Netlify's CDN; those diagnostic runs remain retained. The replacement measurement does not warm the Next process, database pool or any application data before navigation.

The first main matrix with the guarded fallback passed 25 of 48 visits; 23 were slow or unfinished, with a 4.667 s maximum and two first Ask presses that never opened. It measured through initial API completion and the document load. Subsequent normal-basemap checks strengthened completion to include the loaded map and first usable ballot input. Localhost basemap probes were refused by the production key's origin restriction; their fast timings still showed the fallback and are not normal-basemap passes. A buffered browser interception also distorted streaming and delivered decompressed assets through the browser controller; it is replaced by the streaming proxy. The final harness rejects the basemap-unavailable notice, provider HTTP failures and a software map with no successful raster tile response. All failed attempts are retained under `.scratch/rs03/pages/`.
