SRC-GC adds Google Civic voterinfo for the November 3, 2026 election beside the certified state ballots and voting-site holdings. It uses the existing civic candidates, events, promotions and doors. It adds no database table or column; identity-domain classifications remain those of the existing public civic payloads and operational door records.

There is one national routine contract, `google-civic-voterinfo`. The standing runner discovers the exact election ID from `elections`, enumerates every state's held government inventory, and reads voterinfo for each published public office address. Each government has its own promoted scope and source clock. A bounded pass resumes from those clocks. Missing inventories, governments with no office address, reachable empty responses and unavailable address queries are counted separately. The catalog and state summaries report rows loaded, joined and unjoined. These count source observations, including repeated rows from separate address queries, rather than claiming unique contests nationally.

Google offers address queries, not a national bulk voterinfo export. The routine cannot enumerate residential addresses or assert complete nationwide ballot coverage from public-office probes. Every returned source row is kept; only a returned district OCD ID can join a held division. Names and office addresses never create government or person joins. Where the API omits its native district ID, a row remains unjoined. Election IDs and content-bound observation IDs preserve source identity; observation IDs do not pretend to be native contest or site IDs. The civic change model treats each exact scoped query response as one snapshot containing all observations. Changed responses advance that snapshot, while the existing candidate history retains earlier snapshots. This lets changed hours or partial lists refresh without turning an omitted observation into a deletion or absence claim. State reports count the contained source rows, separately from query-snapshot counts.

The election-window clock is daily, weekly afterward. Target clocks use the same contract and retain successful earlier reads during a resumed pass. Requests have no small-government pacing; 429 and 5xx responses honor Retry-After and backoff. The API does not expose a voterinfo publication timestamp or a revision feed, so publication dates remain null and the actual source check is dated separately. Every field stays with the named upstream source and its official flag; Google is attributed as the intermediary. The daily window is a check schedule, not a claim that every upstream government publishes daily.

Reader lookups are POST requests with no-store responses. Addresses stay in the input and tab memory and go to Google for the current address query; normalizedInput, reader addresses and key-bearing URLs never enter the reader result, source evidence, logs or database. Ask uses a fresh lookup when a reader asks about the ballot or voting locations after checking an address. Google results have their own cards, with one bottom Sources list each. Certified state lists retain their independent data and sources.

A failed public-office query creates a SOURCE_BLOCKED candidate and records its door outage and reason. The prior promoted observations remain held. A successful zero-row response is a partial source response, not evidence of no election. Unchanged source bytes or facts confirm a successful check without advancing a different pointer. A reader lookup outage records only a sanitized lookup-door reason after the response, retaining no address.
