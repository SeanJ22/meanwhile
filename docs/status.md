# Status — RETIRED 2026-08-20

**This file is retired. Its replacement is [`docs/tracker.md`](tracker.md).**

Retired by Prompt E item 12, 2026-08-20 (America/Phoenix, from `pnpm stamp`).
Its generator, `scripts/status-report.mjs`, and the `pnpm status:report` command
that ran it are both gone in the same commit — a retired document with a live
generator is not retired, it is one command away from coming back.

## What it was

A generated section-by-section view of `docs/tracker.csv`, written on
2026-08-20 by Prompt C. It sectioned the tracker by the DEPENDENCY GRAPH: a
section was a set of rows where nothing inside it depended on anything in a
later section, so the file read front to back.

## Why it is retired rather than fixed

Three reasons, and the third is the one that matters most.

1. **Its sections answered the wrong question.** Dependency order is correct for
   sequencing a session and useless for answering "where does New Hampshire
   stand", because New Hampshire work was scattered across every section by
   dependency depth. The tracker is now sectioned by AREA OF THE PROJECT
   (`docs/tracker-sections.json`), and dependency information stays on each row
   where it orders rows inside a section.

2. **Its largest section was not a place.** 247 rows — 54% of the tracker — sat
   in "Everything with no recorded prerequisite", because the `Depends on`
   column is sparse and the graph could not tell work with no prerequisite from
   work whose prerequisite nobody wrote down. It said so honestly in place,
   which is the file working as designed and is also the argument for replacing
   the design. The tracker row that carries this is `R56`.

3. **It printed a P0 count over the wrong denominator, and the wrong number
   travelled.** Under a heading about the whole tracker it printed P0 across
   ALL rows, so **93** — every row ever marked P0, including the 83 that had
   already shipped — was read as the size of the top-priority queue. A figure
   near it, 100, was carried forward into two later briefs as the number of open
   P0 rows. **The real open-P0 count was 17, and by Prompt D it was 10.** Both
   figures stated as the pair they always were: **10 open P0 of 141 open rows**,
   against **93 P0 across all 456 rows**. A denominator that can disagree with
   its own page is not a denominator; it is a second opinion presented as
   arithmetic.

The priority scale that produced that figure is gone too. RULING 29 replaced it
with three levels — P1 broken or blocking, P2 needed before the section is done,
P3 wanted but not needed — ranked inside each section and never across sections,
with a cap of five P1 rows per section (RULING 30).

## Where each thing it used to answer now lives

| The question | Where it is answered now |
|---|---|
| What is left, and what is urgent | `docs/tracker.md`, generated by `corepack pnpm tracker:views` |
| What happened, session by session | `docs/log.md`, generated by the same command |
| What is still dark in a place | `docs/gap-ledger.md`, generated by `corepack pnpm ledger:build` |
| The rows themselves, editable | `docs/tracker.xlsx` — Working and Resolved tabs, plus a how-to-use tab |
| The rows themselves, diffable | `docs/tracker-working.csv` and `docs/tracker-resolved.csv` |

The pre-rebuild tracker, `docs/tracker.csv`, is frozen and kept. It is read for
history and never written again; `tests/tracker-stores.test.ts` pins its digest
so that stays true.

Nothing is deleted. This file stays where it is, saying what it said and why it
stopped being true, because the next person to go looking for a status page
should find the reason rather than a missing file.
