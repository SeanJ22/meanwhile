# VS-01 official voting sources

Snapshot: October 13, 2026 UTC. Discovery started with `data/reference/fec_state_election_offices.csv`, then followed official links. No search engine, login, CAPTCHA solution, or voter identity request was used. The 54 FEC office roots cover all 50 states, DC and PR (Kentucky and Rhode Island each have two FEC entries). Root pages are discovery doors with `covers: []`; a homepage is not a polling-place list.

`data/reference/voting-source-doors.json` contains the root doors and discovered routes. `data/reference/voting-legacy-doors.json` separately preserves previously supported official routes, including the existing Cochise PDF, Pima map layers, Morris County and New Hampshire. Door records are acquisition seed data; operational copies and subsequent discoveries live in the existing door registry.

The counts below are facts captured in committed source fixtures, not claims about production publication. Production counts were not queried in this workspace. Initial plain-sandbox requests could not reach the proxy; network-enabled execution resolved that workspace limitation without asking for access. The committed manifest distinguishes original HTTP bytes from earlier browser extracts and normalized representations. Original Montana XLSX, North Carolina polling CSV and full early-voting TSV, North Dakota HTML, voterfocus HTML, El Paso HTML, official rule/calendar pages, Pima app configuration and Census responses are now captured with URL, hash and robots evidence. No acceptance value was invented. Three county HTML captures (Pima election page and both El Paso location pages) have credential substrings replaced through the repository capture boundary. Their manifest entries distinguish original response hashes from sanitized saved hashes; election text and site records are preserved.

For each unfilled county or town, the runtime emits the existing hunter blank with ID `voting-sites:2026-11-03:<jurisdiction OCD id>` and sorts known populations largest first. Every blank records what is owed, actual attempts and the next official route. The route-specific blanks append `:access`, `:extraction`, `:earlier-election`, `:missing-sites` or `:geocode` to the door ID. These are deterministic work identities, not evidence that a production queue write happened here.
