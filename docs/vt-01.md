# VT-01: legislative votes for every state

All 50 states and DC produced source-backed current-session member votes in the production read-only replay. The 52 registered jurisdictions also include Puerto Rico, whose empty/unsupported source results are reported below.

This lane was cut as `stream/vt-01` from River `5307d8b` (main `9a159f6`). These checks made no production mutations. The new source code and reader format are built for River; publication and deployment follow River integration.

## Why votes were missing

- Open States bill fallback requested 100 rows per page. The live API accepts at most 20, returning HTTP 400 for the old request. Tennessee’s current session without a CSV link now receives a successful API check with 20 rows per page; the publisher returned zero bills.
- The national Open States metadata endpoint supplies all jurisdictions in two pages. Replacing one metadata request per state removes the observed request storm: the earlier per-state burst received 42 HTTP 429 responses after ten successes.
- Publisher session metadata uses blank, `regular`, and sometimes incorrect `primary` classifications. Current cycles now follow the publisher’s regular/special names and years, including later special sessions. California’s genuine session identifiers contain spaces; the parser now preserves them and checks decoded source paths.
- An Open States archive can contain no vote files, or votes without exact native person IDs. LegiScan supplies complementary records, but the old crosswalk inspected only official biography/website URLs. Unique shared Ballotpedia/VoteSmart/member profile links now supply independently sourced exact joins. Names never authorize a join. Alabama and Arkansas went from zero joined LegiScan positions to 253,178 and 25,566 in this replay.
- Nebraska’s actual LegiScan chamber code is `L`; it now produces 1,774 rolls and 85,152 member positions. North Carolina’s extra session has `special: 0`; its source name now keeps that special session together with its regular cycle.
- A changed native vote identity previously threw for the entire state. The writer now preserves that earlier verified vote, records the conflict, and publishes neighboring facts. The production comparison found two current North Carolina conflicts; the current New Mexico and Oklahoma cycles had none.

Production initially held 36 Open States national vote projections and zero LegiScan vote projections. Several unpromoted jurisdictions had no candidate at all; that observation establishes missing delivery, without proving their scheduler launch history. Runtime launch priority and Admin order admission remain with CP-01/HN-01. LegiScan’s contract in this River revision is weekly while Open States is daily; that scheduler configuration is outside this lane’s owned files.

## What the run holds

Source archives stream to disk and immutable bounded vault chunks. CSV joins and normalized member positions live in a state job’s temporary SQLite database. LegiScan decodes its base64 envelope to disk and parses one roll at a time. The reader projection carries roll metadata plus immutable per-person page references; a person reader fetches that person’s pages. Existing version-1 data migrates once and keeps its verified history. The old production whole-archive/whole-session position accumulation has been removed.

Every temporary write and SQLite destination uses the existing confinement guard, which checks the OS temporary root, symlinks, and the repository boundary. A repository destination is refused even when the temporary-root environment points there. Fixture-only byte staging lives under tests, outside registered data-command imports. Durable source evidence and reader promotions continue through the existing data plane; audit result data stays outside version control.

Each source job emits peak RSS, runtime, and measured database response bytes through the existing vital-sign counter. The read-only audit uses a local durable evidence vault and real production roster identities, then exercises the same page writer and member reader. It does not exercise production writes or remote object-vault upload latency.

## Memory and RH-01

The largest measured current-session parser + member-page writer + member-reader run was **513,531,904 bytes (489.74 MiB), NY legiscan**. The corresponding Open States maximum was 512,643,072 bytes (488.89 MiB), Tennessee.

The final streamed Illinois predecessor initializer, current-session parser, and page construction peaked at **553,426,944 bytes (527.79 MiB)**. It preserved all 18,099 production rolls and earlier member positions, producing 574,005 positions. Registered publication and the typed historical member reader then passed in an isolated in-memory store, with a complete replay peak of **1,162,178,560 bytes (1108.34 MiB)** and runtime **199,366 ms**. The bounded predecessor query/staging took 167,551 ms and current-session parsing added 11,673 ms; this one-time conversion trades runtime for bounded memory.

That isolated publication store had no old last-known-good candidate seeded. The production candidate lifecycle still reads its old canonical predecessor through the shared database client, which is outside this lane. The earlier whole-predecessor baseline measured **2,705,670,144 bytes (2580.33 MiB)** in **105,320 ms**. The final initializer avoids the owned full-predecessor read, but the isolated 1108.34 MiB result does not measure a complete production writer with that shared legacy reload.

RH-01 should retain the 3,072 MiB reservation until each legacy pointer has moved to the page format. The steady page format supports a lower reservation after conversion; the current-session maximum above is evidence for RH-01, while complete production write/upload overhead remains to be observed. This lane does not edit worker slots or change configured fleet concurrency.

## Reproduce

Use an existing production `readonly` connection in an untracked env file, then run the source and writer replays. The utility writes only its local audit directory. Retained roster snapshots and source bytes avoid repeated unchanged production reads; use a fresh audit output directory for a fresh inventory.

```sh
NODE_USE_ENV_PROXY=1 node --experimental-strip-types --import ./scripts/register-test-loader.mjs scripts/state-votes-check.mts --env=/path/to/readonly.env --source=openstates --phase=writer
NODE_USE_ENV_PROXY=1 node --experimental-strip-types --import ./scripts/register-test-loader.mjs scripts/state-votes-check.mts --env=/path/to/readonly.env --source=legiscan --phase=writer
```
